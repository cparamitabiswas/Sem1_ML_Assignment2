# Student Outcome Predictor

ML Assignment 2 (M.Tech AIML/DSE, BITS Pilani WILP). Five classifiers trained
on one dataset, compared on six metrics, and served through a Streamlit app.

## a. Problem Statement

Predict a student's final academic outcome (Dropout, Enrolled, or Graduate)
using information available at enrollment (demographics, socio-economic
background, admission data), combined with academic performance from the
first and second semesters. This is a 3-class classification problem.
The practical motivation is catching at-risk students early, since a
college can only step in before the outcome is already known.

## b. Dataset Description

[UCI "Predict Students' Dropout and Academic Success"](https://archive.ics.uci.edu/dataset/697/predict+students+dropout+and+academic+success)
(dataset id 697, CC BY 4.0), compiled from a Portuguese higher education
institution across several undergraduate degrees (agronomy, design,
education, nursing, journalism, management, social service, technologies).

- **Instances**: 4,424
- **Features**: 36, all numeric. Some are continuous (admission grade,
  semester grades, unemployment/inflation/GDP at enrollment), others are
  integer-coded categorical (`Course`, `Application mode`, `Marital status`)
- **Target**: 3 classes: `Graduate` (2,209), `Dropout` (1,421), `Enrolled` (794)
- **Missing values**: none
- Full dataset: [`data/dataset.csv`](data/dataset.csv) (citation in
  [`data/SOURCE.md`](data/SOURCE.md)). The held-out test split used for
  evaluation, and by the Streamlit app, is [`test_data.csv`](test_data.csv)
  (885 rows, stratified 20% split, `random_state=42`).

## d. Models Used

All 5 models were trained on the same stratified 80/20 train/test split
(see [`model/train_models.ipynb`](model/train_models.ipynb)). Logistic
Regression and kNN run on standardized features, since they're
scale-sensitive. Decision Tree, Naive Bayes, and Random Forest run on the
raw numeric features. Precision, recall, F1, and AUC are macro-averaged
across the 3 classes; MCC is computed directly for the multi-class case.

| ML Model Name | Accuracy | AUC | Precision | Recall | F1 | MCC |
|---|---|---|---|---|---|---|
| Logistic Regression | 0.768 | 0.878 | 0.707 | 0.675 | 0.683 | 0.615 |
| Decision Tree | 0.729 | 0.813 | 0.673 | 0.658 | 0.664 | 0.554 |
| kNN | 0.715 | 0.829 | 0.679 | 0.594 | 0.602 | 0.527 |
| Naive Bayes | 0.660 | 0.791 | 0.567 | 0.559 | 0.558 | 0.430 |
| Random Forest (Ensemble) | 0.768 | 0.886 | 0.718 | 0.676 | 0.685 | 0.615 |

*(These numbers are generated by the notebook and saved to
`model/metrics.json`, which has the full precision. Re-run the notebook to
reproduce them.)*

## e. Observations

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | A strong linear baseline. It ties Random Forest on accuracy and MCC, which suggests the 3 outcomes are fairly separable along a linear combination of the semester grade and approval-count features. Its weak point is the `Enrolled` class (precision 0.53, recall 0.33). The confusion matrix shows 43 actual `Enrolled` students predicted as `Dropout` and 63 predicted as `Graduate`, so the model treats "still enrolled" as a blend of the other two rather than a pattern of its own. |
| Decision Tree | Weaker than both the linear model and the ensemble on every metric, which is expected from a single tree capped at `max_depth=8`. It trades some fit for less overfitting but still can't match Random Forest's averaging. Interestingly, it gets the best `Enrolled` recall of all 5 models (0.43, versus 0.33 down to 0.19 for the others), meaning its axis-aligned splits pick up a few `Enrolled`-specific patterns the other models smooth over. |
| kNN | Middling accuracy (0.715) hides a real imbalance problem. `Graduate` recall is the highest of any model (0.96), but `Enrolled` recall is one of the worst (0.20). With 36 features, most neighborhoods around a minority-class point end up dominated by majority-class (`Graduate`) neighbors, so kNN ends up predicting the majority class most of the time. |
| Naive Bayes | The weakest model on all 6 metrics, by a clear margin. The feature-independence assumption doesn't hold up well here: 1st- and 2nd-semester curricular unit counts and grades are highly correlated by construction (a student's 2nd-semester performance tracks their 1st), and Gaussian NB can't represent that. It shows up worst on `Enrolled` (precision 0.27, recall 0.18). |
| Random Forest (Ensemble) | Best, or tied-best, on every single metric. Averaging 200 trees fixes almost all of the single Decision Tree's overfitting (every metric improves), while still capturing the non-linear feature interactions Logistic Regression can't, without the heavy majority-class bias that hurts kNN and Naive Bayes. |
| **Overall Winner for your dataset?** | **Random Forest (Ensemble).** It matches Logistic Regression's accuracy (0.768) and MCC (0.615), but leads on AUC (0.886 vs. 0.878), precision (0.718 vs. 0.707), and F1 (0.685 vs. 0.683), and it's far more stable than the single Decision Tree it's built from. All 5 models share the same weakness, the minority `Enrolled` class, but Random Forest handles it best of the five. |

## Repository Structure

```
├── app.py                    # Streamlit app
├── requirements.txt
├── test_data.csv             # held-out test split (885 rows) - upload this in the app
├── .streamlit/config.toml    # app theme
├── data/
│   ├── dataset.csv           # full source dataset
│   └── SOURCE.md             # dataset citation
└── model/
    ├── preprocessing.py      # feature/target config, pipeline builder
    ├── metrics_utils.py      # shared metric computation (notebook + app)
    ├── train_models.ipynb    # trains, evaluates, and saves all 5 models
    ├── metrics.json          # benchmark metrics for all 5 models
    └── saved/*.joblib        # fitted pipelines (one per model)
```

## Running Locally

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

This opens the app in your browser at `http://localhost:8501`. In the
**Evaluate a Model** tab, upload `test_data.csv` from this repo and pick a
model from the dropdown to see its metrics and confusion matrix.

To retrain the models, open `model/train_models.ipynb` in Jupyter and run
all cells. This regenerates `model/saved/*.joblib`, `model/metrics.json`,
and `test_data.csv`.
